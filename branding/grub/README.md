# GRUB theme

Skeleton theme. `background.png` (1920x1080) and the selection/scrollbar slices are generated by `scripts/build.py`.

## Fonts (.pf2)

GRUB needs bitmap fonts in `.pf2` format. The build box that made this kit had no `grub-mkfont`, so the `.pf2` files are not included. On Fedora:

```
sudo dnf install grub2-tools-extra
cd branding
python3 scripts/build.py          # makes src/fonts/.instances/*.ttf
grub2-mkfont -s 18 -o grub/darkjuander/inter_regular_18.pf2 src/fonts/.instances/Inter-opsz14-wght400.ttf
grub2-mkfont -s 16 -o grub/darkjuander/jetbrains_mono_16.pf2 src/fonts/.instances/JetBrainsMono-wght400.ttf
```

If `grub2-mkfont` is on PATH, `build.py` does this for you. The font names in `theme.txt` must match the names GRUB reads from the `.pf2` files; check with `grub2-fstest` or adjust after the first boot test.

## Install

The image definition copies this directory to `/usr/share/grub/themes/darkjuander`, runs `grub2-mkfont` there, and sets `GRUB_THEME` in `/etc/default/grub` to `/usr/share/grub/themes/darkjuander/theme.txt`. The `.pf2` files are not committed. A missing font or a missing `grub2-mkfont` fails the image build.

On a booted system the equivalent manual steps would be:

```
sudo cp -r grub/darkjuander /boot/grub2/themes/
echo 'GRUB_THEME="/boot/grub2/themes/darkjuander/theme.txt"' | sudo tee -a /etc/default/grub
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
```

On bootc systems the bootloader is managed by bootupd. GRUB may only read a theme from the boot partition, and this image has not been booted, so the `/usr/share/grub/themes` path is untested. Confirm it on a real boot before relying on the menu theme.
