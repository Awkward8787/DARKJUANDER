## 1. Brand overview

Name **DARKJUANDER** (always all caps, one word; no "Dark Juander"), owner Anthony Jaamal Jones / Vibe Virtue Enterprise LLC; working name, not a registered trademark (no ®). Sub-brand **UMBRA** = the neural core (Unified Model, Buffer and Routing Architecture); a component name only, written "the UMBRA core", because the UMBRA mark is crowded. Positioning line (`branding/brand-guide.md` v1.0): "DARKJUANDER is a Linux workstation for people who run AI agents every day and want each one inside a boundary they can inspect, limit, and audit." Audience: terminal-comfortable developers, solo founders, security people already running coding agents and local models.

**Taglines** (five options in the guide). Recommended and used in the README: **"Agents inside a boundary you can audit."** Secondary technical line: "Every model call, labeled and logged." Others: "Run your agents in the dark.", "Your machine. Your models. Your rules.", "Local by default. Logged by design." Owner confirmation UNCONFIRMED.

**Voice traits**: Exact (name the mechanism, command, file), Honest about limits (say what is planned), Quietly confident (short sentences, no hype). Words avoided: hacker, elite, unhackable, military-grade, bulletproof, revolutionary, game-changing, next-gen, unleash, seamless, leverage. Mechanics: sentence case headings, numerals, commands in code, no exclamation marks, no em dashes.

Differentiation (`research/competitors.md`, 2026-10-28): Kali, Parrot, Qubes, Tails, Whonix, BlackArch and Universal Blue/Bluefin sell tools or compartments; DARKJUANDER sells an agent boundary. Violet on near-black avoids Kali blue, Parrot cyan, BlackArch red and Tails' mid purple on light.

## 4. Copy rules (from the repo docs)

State what works and what does not; label targets as targets; never claim enforcement the code does not have; no hype. Example: "Passing them does not mean DARKJUANDER enforces the PRD threat model." The brand guide adds: describe planned items as **planned**; never claim a bootable download, signed images, desktop, or 7.9 targets as available until true; never say private data "cannot leave the machine" (the tested behavior is a hard rule in a mock-engine demo).

## 5. Accessibility design rules

Contrast pairs above; body text only lumen_100/ash_400 on dark and umbra_950 on light; never violet text on violet_deep or on lumen_50 at small sizes; denied actions use danger red plus an icon, never color alone; violet reserved for focus and brand; approval prompts must be visually distinct from anything an agent can draw (planned trusted dialog). No GUI exists yet beyond Plymouth.

## 6. Do and don't

Do: use the supplied SVG/PNG; dark version on umbra_950/umbra_900, light version on lumen_50/white, mono when one color; switch to `icon-small` below 40 px; show the label and route that applied and why something was denied; label mockups "Concept, not shipped".

Don't: redraw, retype or re-track the wordmark; recolor or add gradients, glows or shadows; rotate, stretch or outline; move the crescent or change the route; put the dark version on mid-gray or busy backgrounds; add skulls, hoods, masks, padlocks or code rain; make lockups with other logos without approval; use ®; imply a security certification; hide cloud egress; add telemetry.

## 7. Glossary

| Term | Meaning |
| --- | --- |
| DARKJUANDER | Working name of Jaamal's AI-security Linux OS (Vibe Virtue Enterprise LLC); trademark not searched |
| UMBRA | Working name of the userspace "neural core": model registry, trust-partitioned prefix cache and label/PSI-aware router (`services/umbra`, daemon `umbrad`) |
| dj-base | The hardened Fedora bootc 45 image defined by `image/Containerfile` |
| bootc | Image-based Linux: the OS is shipped as an OCI container image with read-only root and A/B updates |
| Label | Pair of integrity (`trusted`/`untrusted`) and confidentiality (`public`/`private`/`secret`) plus origin and owner; joins take the stricter value |
| Session floor | Highest confidentiality a session has touched; once raised, later calls in that session keep it |
| Span handle | Opaque id returned instead of private file bytes by a mediated read |
| PSI | Linux pressure stall information (`/proc/pressure/memory`), used as a router input |
| Principal | A caller identity in `umbrad.yaml` with bearer token, trust domain, `local_only` and grants |
| Grant | Capability string such as `model.use:default-chat`, `files.read:<path>`, `provider.use:xai` |
| Approve decision | Policy result that needs a human prompt; there is no trusted dialog yet, so it is logged and denied (fail-closed) |
| dj-auditd | Separate signer daemon (user `dj-audit`) that signs audit checkpoints with an ed25519 key |
| SIWC | Sign in with ChatGPT, OpenAI's public-client flow used by `dj provider login openai` |
| Umbra Eclipse | Recommended and default logo direction (direction A, `branding/BUILD_DIRECTION` = `eclipse`): dark disc over a violet crescent with a three-node route inside |
| GHCR | GitHub Container Registry; release images go to `ghcr.io/awkward8787/darkjuander` |
| cosign (keyless) | Sigstore signing tool; signs with a short-lived Fulcio certificate bound to the GitHub OIDC identity `…/release.yml@refs/tags/v…`, logged in Rekor |
| Dry run | `release.yml` run from `pull_request` or `workflow_dispatch` with `dry_run` true; builds artifacts but never publishes, version `0.0.0-dry.<12 hex>` |
| Smoke test | `scripts/smoke-qemu.sh`: boots the qcow2 under QEMU on the runner and requires multi-user target, `UMBRAD_SOCKET_OK`, the PAM password-expiry prompt, a completed password change and `sudo` accepting it |
| Staging tag | `ci-<run id>[-arch]` tags the publish job pushes before signing; internal, never to be `bootc switch`ed to |
| Base image mirror | `ghcr.io/awkward8787/fedora-bootc`, a GHCR copy of the Fedora bootc 45 index pinned in `image/fedora-bootc.digest`; written only by `scripts/mirror-fedora-bootc.sh --write` from `main` |
| Pin tag | Mirror tag `45-` plus the first 12 hex digits of the pinned digest (`45-479ad7d16893`); never moved to another digest |
